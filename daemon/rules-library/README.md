# Rules library

Ready-made decision rules. Each file defines `direct:library-...` routes. To use one:

1. Copy it into `routes/` (Camel loads and hot-reloads everything there).
2. Call it from the matching branch of `routes/decisions.yaml`, e.g. in `decide-dns`:

   ```yaml
   - simple: "${header.FakenetQname} endsWith 'tunnel.example'"
     steps:
       - to: direct:library-dns-txt-tasking
   ```

A library route answers by setting the body (and FakenetRoute); leaving the body empty
keeps the nucleus's default, as everywhere else.

| File | Route | What it plays |
|---|---|---|
| `staged-http-c2.yaml` | `direct:library-staged-http-c2` | A beaconing HTTP C2: register on first contact, hand out tasks in order (from `fakenet.library.tasks`), accept uploaded results |
| `dns-txt-tasking.yaml` | `direct:library-dns-txt-tasking` | DNS-tunnel-style tasking: TXT answers carry base64 tasks; A answers encode "nothing to do" / "go" |
| `irc-botnet.yaml` | `direct:library-irc-botnet` | An IRC C2 channel: the topic and a PRIVMSG carry commands when the bot joins |
| `kill-switch.yaml` | `direct:library-kill-switch` | Kill-switch domains (`fakenet.library.kill-switch-domains`) answered so the sample stops — or, with `fakenet.library.kill-switch-mode=nxdomain`, so it keeps going |
| `recorded-example.yaml` | `direct:decide-recorded` | Generated by `fakenet-nucleus --rules-from-har`: replays a recorded C2 exchange |

Tasks and domains are properties, so they can change without editing the rules. (Inside
Groovy scripts, read properties with `camelContext.propertiesComponent.resolveProperty(...)`
and avoid `{{`/`}}` in the script text: Camel would parse them as its own placeholders.)
